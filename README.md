# DevOps Test Task

## 1 Вопросы

### 1. Чем git pull отличается от git fetch?

git fetch - загружает изменения из удалённого репозитория, но не изменяет текущую локальную ветку.

git pull - сначала выполняет получение изменений из удалённого репозитория, а затем интегрирует их в текущую ветку(соответствует git fetch + git merge).

### 2. Чем в Linux отличается soft link от hard link? Какое поведение будет при удалении файла оригинала? Можно ли создать hardlink на директорию?

Soft link(symbolic link) - указывает на имя пути файла.
Если удалить оригинальный файл, symbolic link останется, но он будет указывать в пустоту.

Hard link - указывает напрямую на данные на диске(inode).
Данные на диске не удалятся, т.к. жесткая ссылка -это копия указателя, данные физически сотрутся только если удалить все существующие жесткие ссылки на этот файл.

Hard link на директорию стандартной командой создать нельзя Linux чтобы предотвратить появление циклов в структуре файловой системы.

### 3. Как проверить сетевую доступность между двумя Linux машинами?

ping - проверка сетевой доступности
nc - проверка доступности конкретного TCP-сервиса

Проверку можно выполнять на двух уровнях.

1. Проверка сетевой доступности хоста(проверка ICMP-доступности второй машины и наличие потерь пакетов, но ICMP может быть заблокирован firewall): ping -c 4 <IP>

Проверка маршрута до удалённой машины: traceroute <IP> или mtr <IP>

2. Проверка доступности конкретного сервиса или порта(проверка возможности установить TCP-соединение с SSH-портом): nc -vz <IP> <PORT>

Проверка нужного порта на принимающей машине: ss -lntp

### 4. На каких компонентах Linux основана контейнеризация в Docker?

Основными механизмами Linux, используемыми для контейнеризации, являются:

- Пространства имен(Namespaces) - обеспечивают изоляцию процессов, сети, файловых систем, пользователей и других ресурсов.
- Контрольные группы(Cgroups / Control Groups) - позволяют учитывать и ограничивать использование ресурсов(CPU, память, скорость чтения/записи на жёсткий диск или SSD).
- Многослойные файловые системы - файловые системы, которые послойно накладывают директории друг на друга, объединяя их в одну виртуальную папку.
- Слой безопасности: Capability - отбирает у контейнера опасные права, Seccomp - блокирует контейнерам доступ к потенциально опасным вызовам ядра Linux.

### 5. Почему вместо "COPY . . / RUN npm install" рекомендуют делать "COPY package.json / RUN npm install / COPY . ."

Вариант 1:
```dockerfile
COPY . .
RUN npm install
```
При изменении строчки кода кэш сбросится на первом шаге.
Вывод: Docker заново копирует весь проект и каждый раз заново скачивает все библиотеки.

Вариант 2:
```dockerfile
COPY package.json .
RUN npm install
COPY . .
```
При изменении строчки кода, но без правок списка библиотек, Docker видит, что package.json старый, и берет скачанные библиотеки из кэша.
Вывод: Тратится время только на то, чтобы скопировать обновленные файлы кода из последнего шага.

Вывод: ускорение повторной сборки Docker image.

### 6. Могут ли два контейнера внутри одного пода в Kubernetes слушать один и тот же порт?

Нет, два контейнера внутри одного пода слушать одинаковый порт не могут. Появится ошибка после запуска второго контейнера.

### 7. Какие виды JOIN знаете и чем они отличаются?

- INNER JOIN - возвращает строки, для которых найдено совпадение в обеих таблицах.
- LEFT JOIN / LEFT OUTER JOIN - возвращает все строки из левой таблицы и совпадающие строки из правой таблицы. Если совпадения нет, поля правой таблицы содержат NULL.
- RIGHT JOIN / RIGHT OUTER JOIN - возвращает все строки из правой таблицы, плюс совпадающие строки из левой таблицы. Если совпадения нет, поля левой таблицы содержат NULL.
- FULL JOIN / FULL OUTER JOIN - возвращает все строки из обеих таблиц. Для строк без совпадения недостающие значения заполняются NULL.
- CROSS JOIN - возвращает декартово произведение строк двух таблиц(каждая строка из первой таблицы соединяется с каждой строкой из второй таблицы).
- SELF JOIN - таблица объединяется сама с собой(таблица содержит иерархические структуры).

### 8. Что такое having в SQL запросе? Чем отличается от where?

HAVING - это оператор фильтрации, который используется для отбора данных после их группировки(GROUP BY) и работает с результатами агрегатных функций.

WHERE - это оператор фильтрации строк до выполнения группировки и агрегирования.
